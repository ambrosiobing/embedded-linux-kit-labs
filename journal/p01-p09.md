# P01 and P09: one publisher, and two scenes that must stay quiet

The labs are [LTE Cat-4 motion-triggered gateway](../chapters/01-lte-cat-4-motion-triggered-gateway.md)
and [NanoPi NEO Air headless hub](../chapters/09-nanopi-neo-air-headless-hub-and-honest-emmc.md),
and their shared publisher was written on **Saturday 17 October 2026**.

## Why one program

Both chapters already said so. P09's step 3 reads "reuse the P01 publisher
with bus number 0, the only edit is the constructor", and the dead band, the
magnitude and the cool-off are identical in both.

So writing two programs would have been writing down the same decision twice
and waiting to see which copy drifted first. The bus number is an argument,
`--bus 1` for the Pi and `--bus 0` for the NanoPi, and it deliberately has no
default: the only two values it takes belong to different chapters, and a
wrong one looks exactly like a missing sensor.

This is the fourth piece of shared code in the volume and the only one that
was never lifted from anywhere. The other three moved out of a program when
a second one needed them. This one started shared because two chapters had
already specified it that way, and all the arrangement cost was reading them.

## The rule the suite is built around

**The decision is on the magnitude and its distance from one gravity, never
on a single axis.** Two scenes exist to hold it there, and both must produce
nothing at all:

A sensor lying on its side still reads one gravity. It has moved to a
different axis, and nothing has happened. A threshold on any single axis
calls that an event, so a board picked up and set down differently publishes
a shock that never occurred.

Free fall is the same error from the other side. Zero gravities is exactly as
far from rest as two gravities, in the other direction, and a threshold
watching only for a high reading misses a board falling off a bench.

One comparison gets both right, and the volume's existing habit of writing a
scene that must stay quiet is what turns that from a claim into a check.

## The sign extension, which is half of the decode

Two bytes arrive low first and they are two's complement. Minus one gravity
is `0xFF00`, not 65280 counts of acceleration. A missed sign extension
produces an enormous magnitude and an event on every sample, which looks
exactly like a broken sensor and sends a bench chasing the wiring.

The suite checks the case that catches it: upside down reads minus one
gravity on z, and its magnitude is still one, which is what makes lying
upside down not an event.

## P09's question, asked before the run

On the NanoPi the cool-off is a wear control as well as a rate control, which
the chapter says in a sentence and the program now says in numbers. Every
event appended to the log is a write to flash soldered to the board, and that
flash cannot be replaced when it tires.

An hour at twenty hertz of a surface that never settles is 72000 samples.
Without the cool-off that is 72000 appends and three and a half megabytes;
with it, 1800 and eighty kilobytes. A factor of forty, from one timestamp.

The fsync figure is the other half, and it is the one worth printing. The
chapter says to commit on a timer rather than per sample, and the number that
says whether you did is **fsyncs per event**: below one means a timer, above
one means the interval is shorter than the cool-off and the flash is being
committed to when nothing has been written. Both cases are in the suite.

## A format that would have disagreed with itself

Found before anything was compiled, by reading the two halves together.

The parser took base zero, so `0x10` and `16` both worked and meant different
things. The scene writer emits plain hexadecimal with `%02x`. Base zero reads
`fe` as an error and `010` as eight, so **the program would not have been
able to read the files it writes**, and the first symptom would have been a
replay reporting every line malformed.

One base now, hexadecimal, because that is what the device returns, what a
bench capture records and what this program writes. The header says so where
the format is declared, rather than leaving the two sides to agree by
accident.

## What is only a claim, as of Saturday 17 October 2026

**None of this has been compiled.** `STATUS.md` leaves both labs at
**written**.

The live read is the part worth naming. It is Linux only, it is compiled
wherever the checks run, and it has never had a bus to answer it. It opens
`/dev/i2c-N`, sets the slave address with an ioctl, writes the register
pointer and reads six bytes, which is the ordinary i2c-dev sequence and is
not the vendor's business the way P05's acquisition was. What it has never
done is receive an acknowledgement from a real device, and the first thing
the sensor will test is whether the two configuration writes land in the
order this program sends them.
